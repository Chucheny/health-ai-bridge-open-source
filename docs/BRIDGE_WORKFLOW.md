# 统一本地任务入口

总体关系见 [整体框架](ARCHITECTURE.md)。统一入口把网页睡眠与运动的准备、确认上传、回执和查询选择接到原后端，不自动采集、不自动调用 MCP。Node.js 24 及原项目依赖即可运行。

## 开始使用

Windows 可先打开本地工作台：

```powershell
./tools/Bridge.ps1 -Action desktop
# 也可直接启动；首次用系统现有编译器生成本机程序
./tools/Bridge-Desktop.ps1
```

工作台为本项目的独立 Windows 窗口，调用同一 Node 任务层，不是新服务。需要 Windows、PowerShell 7、Node.js 24 和系统已有的 .NET Framework 4.x 编译器；缺失时明确停止，不自动安装组件。C# 源码位于 `tools/bridge-desktop/Workbench.cs`，生成程序只在 ignored 的 `.tools/bridge-desktop/`；换电脑应通过启动脚本重新构建。

界面流程：

1. 明确选择睡眠/运动类别和已提供的 JSON 文件；分别勾选开始、结束日期，按北京时间计算，结束日期包含当天。未勾选不使用控件显示的当前日期。可先点击“仅预检，不创建任务”查看范围、数量、预计请求大小和采集覆盖限制；需要保存时点击“创建本地任务（重新预检）”，会重新读取文件并校验，原文件保持。也可直接创建任务，仍先完成同一预检。
2. 点击“刷新任务列表”才枚举统一任务目录中的 UUID 文件夹，每页20项，只列任务编号，不读任务正文、私人配置或健康采集文件。列表不是新旧排序，不自动选择第一项。明确选中后点击“查看 / 刷新状态”，才读取该任务并重算预检摘要。
3. 配置通过文件选择器指定，终端读取所选路径。查看任务后，可打开上传确认终端，由原命令展示目标、身份声明和日期，并要求完整确认语句。终端打开时，同一工作台的上传按钮禁用。关闭后点击「查看 / 刷新状态」核对回执。
4. 成功回执状态显示云端提交时间和本批接收条数。运动另显示新增或更新条数，睡眠显示快照 ID 以及本批新建或复用。此时可生成查询参数或手机使用说明，再按需复制到已连接原插件的手机 ChatGPT。说明含日期和睡眠快照标识，包含分页指引。切换或刷新任务后需重新生成。远端其他睡眠快照的目录选择在原菜单第6项。

启动工作台后，显式选择要查看的文件或任务。上传确认在独立终端进行，取消后任务仍可用于下次确认。关闭终端后手动刷新回执状态。[工作台说明](../tools/bridge-desktop/README.md)

2026-11-15已补验工作台截图和文件选择器打开；后续输入仍受电脑操作工具权限限制，完整流程继续待验。任一本地操作失败时，工作台清除旧详情及可复制内容，禁用上传、查询与说明生成；保留任务编号供重新查看，不使用上次成功结果冒充本次结果。重新预检或刷新/翻页时也先清除对应旧选择/旧页，失败不自动重试。

原命令菜单继续可用：

```powershell
./tools/Bridge.ps1
```

菜单提供查看框架、准备任务、查看任务、确认上传和选择已确认任务的查询参数。第6项从云端睡眠目录选择快照并生成手机说明，第8项由本地任务回执生成手机说明，第9项仅预检。也可运行 `./tools/Bridge.ps1 -Action preview`，或直接运行以下 Node 命令。

```powershell
node ./backend/bridge-command.mts overview
node ./backend/bridge-command.mts list
node ./backend/bridge-command.mts list "<上一页nextCursor>"
node ./backend/bridge-command.mts preview sleep "<睡眠采集文件>" "<授权开始ISO>" "<授权结束ISO>"
node ./backend/bridge-command.mts preview activity "<运动采集文件或记录数组>" "<授权开始ISO>" "<授权结束ISO>"
node ./backend/bridge-command.mts prepare sleep "<睡眠采集文件>" "<授权开始ISO>" "<授权结束ISO>"
node ./backend/bridge-command.mts prepare activity "<运动采集文件或记录数组>" "<授权开始ISO>" "<授权结束ISO>"
node ./backend/bridge-command.mts inspect "<任务ID>"
node ./backend/bridge-command.mts upload "<任务ID>" "<独立Bridge设备配置>"
node ./backend/bridge-command.mts queries "<明确选择的任务ID>"
node ./backend/bridge-command.mts chatgpt "<明确选择的任务ID>"
```

overview/list/preview/prepare/inspect/queries/chatgpt 均不联网。upload 必须真实交互终端，非交互在打开配置前拒绝；核对类别、日期、账号/安装与 HTTPS 目标，输入完整确认语句后才发送一次请求。没有自动重试或默认账号/日期，不自动查找私人配置。

preview 使用与 prepare 相同的类别、日期、记录、精度及请求大小校验，只返回 `validated_locally_no_task_created`、类别、范围、统计、预计请求大小和覆盖限制，不输出任务ID、批次ID、请求体或哈希，不创建目录或文件，不读取私人配置。预览不是可上传任务、上传确认或真实取数/发布证明；重复预览不增加任务。输入改变后工作台清除预览；文件被外部改动时显示仍只代表上次读取，真正 prepare 会重新读取和校验，不复用内存预览或自动创建任务。

## 输入和文件

- 睡眠支持现有采集文件。运动支持首批采集文件、0.3.0 续读采集文件和顶层记录数组。续读文件包含最多 5 页，按单文件选择。工作台仍支持多选首批文件合成一个任务。[采集助手用法](../tools/trainingcamp-browser/README.md)
- 预检独立校验请求单位、逐页时间边界、条数和实际记录。任务使用获授权的采集窗。原响应保留在采集文件里，任务按原运动协议保存需要的记录字段。
- 时间必须显式含时区、开始包含/结束不包含，最多31天。睡眠采集窗必须在独立授权窗内；运动完整起止须在调用者指定窗内。
- 运动每任务最多100条、请求体不超过2 MiB；未实现跨任务自动分批。采集文件较大时明确失败，不静默裁剪。源端完整性仍未知。
- 统一任务保存在 ignored 的 `private/bridge-imports/<任务ID>/`：job.json（含健康数据）、destination.json（目标声明，不含 token）、receipt.json（匹配任务的回执）、queries.json（仅显式选择后保存）、chatgpt.json（仅生成手机说明后保存）。原文件不移动/覆盖，不把这些文件放 Git。
- prepare 固定请求体/批次，inspect 重算预检摘要，不信任被修改的展示字段。运动输入不安全整数先保留原十进制位数；无关设备元数据不写入新任务请求。

新任务先在同一任务父目录的 `.preparing-<任务ID>/` 内设置私有访问权限，再独占写入完整 `job.json`、同步文件并关闭，最后将整个目录改名为正式UUID目录；只有此后才返回准备成功。任务列表仍只枚举UUID目录，不读任务正文，因此未完成目录不会冒充可用任务，也不能交给 inspect/upload/queries/chatgpt。旧UUID任务继续沿用原格式与校验，不自动改名或修复。

保存或发布失败返回 `import_task_not_saved`，本次没有上传；原输入和可能留下的 `.preparing-` 文件保留，供核对权限、空间和写入问题，不自动删除、覆盖或恢复。此类文件可能含健康正文，仍须保持在 ignored 的 private 中。核对后可重新创建任务；该提示不等同于上传过程中的结果未知或回执保存失败，后二者仍应保留原任务重试。故障回归覆盖普通写入、文件同步和最终改名失败，不代表断电或磁盘故障恢复已验收。

新任务的本地 `inputFormat` 区分 `activity_first_response_capture`（运动首批）、`activity_first_response_set`（多份运动首批）、`activity_bounded_scroll_capture`（运动续读）、`activity_record_array`（运动数组）与 `sleep_capture`（睡眠单次响应）。预检、任务详情、上传确认和手机说明根据该格式生成固定的 `collection` 提示。源数据完整性为未知。后端游标只表示当前查询结果是否遍历完毕。

该字段仅为本地输入格式记录，不是来源真实性证明、权限或覆盖认证；不能增加日期/类型授权，不进入原上传 body、请求哈希、回执或 MCP 参数。没有此字段的旧任务按 `legacy_unspecified` 显示采集方式未知，不猜测首批或全量，也不自动迁移或重写文件。

### 运动多文件预检

在工作台先选运动类别，再在文件选择器多选同一账号的 2 至 31 份运动首批文件。CLI 可在 `activity` 后加 `--captures`，依次列出文件路径，最后给出独立的授权开始和结束时间。创建任务使用相同参数，把 `preview` 换为 `prepare`。

```powershell
node ./backend/bridge-command.mts preview activity --captures "运动一.json" "运动二.json" "2026-01-01T00:00:00+08:00" "2026-01-04T00:00:00+08:00"
```

每份文件按原首批规则校验，文件的采集窗口须在授权范围内且相接或重叠。相同来源记录 ID 的版本和保留内容一致时只保留一份，存在冲突时整组拒绝。任务采用实际窗口合并后的范围，仍受 31 天、100 条和 2 MiB 上传数据限制。首批文件不含用于核验账号的标识，需自行确认来自同一账号。

多选能把不同窗口已取得的运动记录用于一次导入。任务、上传确认与手机说明仍标为完整性未知。每份文件最多包含 20 条记录，跨窗记录也可能漏读。

## 状态和失败恢复

inspect 显示的状态见 [任务状态](ARCHITECTURE.md#任务状态与信任边界)。取消上传不保存目标、不发请求。确认后保存目标再发送；同任务不能更换 origin、owner/source，token 轮换但目标声明相同可继续使用。配置声明不等同于已核实的服务端身份。

只有本地目标绑定有效、回执与原任务匹配时，`inspect` 才返回 `receiptSummary`。Windows 工作台将提交时间显示为北京时间。睡眠预检和任务详情显示从采集文件重算的分期数，CLI 字段为 `counts.sourceStages`。用同一日期范围和快照 ID 对照手机读回的会话数及分页重组后的分期总数。运动的接收和新增或更新条数描述这个导入批次，手机查询返回所选日期窗内的实时运动记录，可能包含其他批次。

upload 在显示确认前先只读核对已有文件：目标绑定须有效并与配置的 origin/owner/source 一致；已有回执必须有目标绑定且匹配当前任务。回执不可读、超限、损坏、哈希不匹配或缺失绑定时拒绝；绑定损坏或配置不匹配也拒绝，均不发请求、不覆盖证据。用户确认后、保存目标和发送前再次核对，不能仅沿用确认前的检查结果。配置换 token 但目标声明相同仍可进入确认；凭据是否有效继续由原服务端验证。

仅回执文件缺失不视为冲突，可用于初次上传或原目标下的显式同任务恢复；已有有效回执的明确重试行为也保留。若实际请求完成后才出现本地保存问题，仍报告 `uploaded_receipt_not_saved`，不误报为未发送。确认前后检查不提供跨进程文件锁，也不自动修复文件；核对已存在的冲突后再决定后续操作，不能靠重传覆盖损坏或改投其他账号。

确认前后的核对还会重新读取并校验 `job.json`，对比数据类别、原请求哈希和本地输入格式；任务缺失、损坏、变成非普通文件或实质内容改变时返回 `upload_task_changed`，不发送、不替换为新内容。仅JSON排版或可重算preview字段的变化不改变实际请求，仍按原校验结果处理。请求始终使用展示确认时那一份已校验的内存内容。

收到匹配的服务端成功回执后，保存前再核对任务、绑定及现有回执，且此时要求原目标绑定仍存在。若在请求期间被改动，不把回执写到已改变的任务或目标上；保留现场，报告 `uploaded_receipt_not_saved`。恢复操作必须先核实原任务与原目标，不能将此错误当作“没有发送”或直接使用替换任务重试；不自动恢复原文件。原来源、日期授权、上传体、回执及服务端幂等协议保持。

`bridge_outcome_unknown` 可能是云端已保存而响应丢失；保留原任务，核对后明确重试同一任务、批次与目标，不重新 prepare。`uploaded_receipt_not_saved` 表示收到成功回执但本地保存失败，同样保留原任务/文件，处理后明确重试。目标、回执或查询文件冲突时保留原文件，不覆盖证据，也不自动修复或上传。

统一命令的失败输出由 `backend/bridge-errors.mts` 生成固定的 `error`、中文 `message`、`recovery` 和 `automaticRetry=false`，不会拼接文件路径、凭据、健康正文或服务端错误响应。Windows工作台显示同一条原因及“下一步”，异常后仍清除旧结果并要求重新查看任务；输出格式损坏、错误码未知或字段超限时只显示固定通用提示。旧睡眠命令的错误格式保持兼容，不由本次改动重写。

- 文件不存在、无法读取、JSON/UTF-8损坏或超出输入大小限制：停止本次准备，提示核对明确选择的本地文件，不创建任务。此提示不精确区分具体文件系统原因。
- 401：核对凭据是否有效；更新凭据仍需保持原目标和账号/安装绑定。403：核对权限、允许类型及来源开关，不能仅凭状态码断定原因。404：核对目标部署是否提供接口，不自动部署或启用来源。
- 409：保留原任务、批次及回执核对冲突，不重新生成批次绕过。413/415：核对请求上限或协议版本，不自动裁剪、拆分或转换。429：停止本次请求，保留原任务，需要时手动核对并重试。
- 结果未知与已确认但本地回执未保存分别提示；二者都保留原任务，不重新 prepare，也不自动重试。已有目标绑定不代表服务端已经保存。

## 显式选择查询

queries 是用户明确选择某个已确认任务的动作，要求有效的目标绑定和匹配该任务的回执：

- 睡眠：生成该任务回执中 snapshotId 的 `health_records`（带 sleepStages=paged）和 `health_summary` 参数。不按采集/导入时间猜“最新”，不合并其他快照。要从云端目录选其他快照，使用菜单第6项或原 `TrainingCamp-Sleep.ps1 -Action select`。
- 运动：生成该任务明确日期窗中的 ExerciseSessionRecord 参数。运动查询是实时来源视图，可能包含同窗其他批次；不把它称为该批次的固定快照或去重总量。

生成参数不调用 MCP，也不绕过客户端/服务端原 OAuth 账号绑定、类型及日期授权。不要把任务中的 Bridge 上传凭据交给 ChatGPT；任务文件本身不保存该 token。

## 交给手机 ChatGPT

在工作台核对所选任务回执后点击“生成手机使用说明”，或使用菜单第8项。Node `chatgpt` 命令返回 JSON，其中 `prompt` 是可复制的中文说明；PowerShell 菜单直接显示该文本。说明连同两项工具参数保存在该任务的 `chatgpt.json`，仅由原任务与匹配回执重新推导，不读取已有导出作为可信输入，也不依赖先生成 `queries.json`。

说明要求先读取计数/时间摘要，再按原参数逐页读取记录，只更新 `cursor` 直到 `nextCursor=null`；睡眠按会话键和分期偏移重组，运动明确为可能包含其他批次的实时视图。错误、重复游标或无法继续时说明部分结果并停止，不自动换来源、范围或快照，不把缺失补零或把每次运动汇总说成全天指标。这是发送给模型的使用指引；实际权限、来源与范围校验仍由原 MCP 执行，不能保证模型逐项遵守文本。

有 `inputFormat` 的新任务还会把该输入格式的固定覆盖限制写入手机说明及导出的 `collection`，明确运动首批上限或数组采集方式未知。旧任务继续生成原格式和原文本，已有 `chatgpt.json` 可以重复使用；其通用说明仍要求完整性和新鲜度未知。原 `queries.json` 格式与两项工具参数不变。输入格式记录不等于运动实时查询窗中所有其他批次的采集来源证据。

已在云端的睡眠快照可用菜单第6项选择。先提供独立 Bridge 配置和要查找的日期，再输入本页快照编号。选定后保存原 `selection.json`，终端显示可复制的中文说明。说明采用所选快照自身的日期和标识，含两项查询参数与睡眠分期拼接规则。联网范围为快照目录，手机上的查询仍由用户发送。详见[睡眠快照目录](TRAININGCAMP_LOCAL_IMPORT.md)。

只有目标绑定及匹配成功回执齐全才允许生成；服务端结果未知、文件损坏或回执缺失均拒绝。重复生成相同内容复用原文件，内容冲突或不可保存时明确失败，不覆盖、不自动修复。已存在说明也不能绕过再次核验。说明含日期/快照等查询元信息，仍保存在 private，不应公开。

用户自行核对手机插件连接的账号与上传任务账号一致，并决定何时发送。生成、查看和复制均为本地操作。网页来源已正式启用，合成联调通过。手机端需使用已刷新工具定义的连接，确认可选网页来源和睡眠快照后再发起实际查询。

## 兼容和当前边界

原 `TrainingCamp-Sleep.ps1` / `trainingcamp-sleep-command.mts` 与 private/trainingcamp-imports、trainingcamp-choices 保持原格式和路径。旧任务继续使用旧入口，不把旧任务ID交给统一入口，也不自动迁移私人文件。两者复用相同的睡眠校验、HTTPS传输及文件一致性逻辑。

本入口使用同一后端、数据库和两项只读 MCP。部署者可在自己的实例应用网页来源迁移并单独启用功能。[自托管后端](../backend/SETUP.md)
