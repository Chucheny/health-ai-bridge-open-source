# Health AI Bridge 架构

| 层 | 实现 |
| --- | --- |
| Android | Health Connect 前台读取、选定类型同步、加密配置与待传队列、WorkManager 调度 |
| 网页采集 | 已登录浏览器内按所选类别和日期读取，保存本地文件 |
| 本地导入 | 独立授权窗、离线预检、上传前显式确认、固定批次和回执 |
| REST 与存储 | 设备凭据约束账号、安装实例和类型，事务写入，幂等重试，PostgreSQL 来源隔离 |
| MCP | OAuth 身份绑定，`health_records` 和 `health_summary` 使用只读事务 |

## 任务状态与信任边界

就绪任务保存已验证的请求体和批次。明确确认后绑定 HTTPS 目标，匹配回执保存后才生成查询参数。遇到响应丢失时，核对状态并重试相同任务、批次和目标。详情见 [导入流程](BRIDGE_WORKFLOW.md#状态和失败恢复)。

Android 端持久化原请求。继续待传队列或上传连接中断时，使用批次 ID、记录类型、序号和原请求的 SHA-256 向 `POST /api/health/sync/receipt` 查询。后端仅匹配同一账号和安装实例的已提交回执。旧版本缺少查询能力或摘要时，客户端可重放同一个原请求，沿用服务端幂等处理。

## 查询边界

默认来源是 Health Sync。训练营运动查询读取日期范围内已保留的运动记录，训练营睡眠查询选定导入回执中的快照。睡眠分期可分批返回，按 `sessionKey` 和 `stagePage.startIndex` 重组，继续读取至 `nextCursor=null`。查询结果的分页结束仅描述该查询的可见范围。来源新鲜度和覆盖范围分别保留其可确认状态。

## 隐私操作

手机单独授权本机读取和所选类型的上传。撤销某设备上传凭据后，账户历史记录仍可保留。账户云端清除操作需使用相应凭据并主动确认，Health Connect 的原始数据仍由系统管理。ChatGPT 连接和授权由 OAuth 单独控制。
